The default constructor for Hamiltonians now correctly sorts by qubit index and combines like terms, so something like:

```python
from qilisdk.analog import Hamiltonian, PauliX, PauliZ

a = Hamiltonian({(PauliX(1), PauliZ(0)): 1.0})
b = Hamiltonian({(PauliZ(0), PauliX(1)): 1.0})
print("a + b:", a + b)
```

actually results in the correct object, which here is `2 Z(0) X(1)`, but previously would have been `X(1) Z(0) + Z(0) X(1)`. Note that this bug wouldn't have happened with the X and Z constructors (`from qilisdk.analog import X, Z`) which is how most people would construct a Hamiltonian.
